# CAPD Maintenance (GSC · SCGC)

เว็บแอประบบแจ้งซ่อมและบำรุงรักษาของแผนก CAPD
- หน้าเว็บ: HTML/JS ล้วน โฮสต์บน GitHub Pages
- ข้อมูลและไฟล์: Supabase

เว็บ: https://phatphisut2011-svg.github.io/capd-maintenance/

```
index.html, css/, js/app.js    หน้าเว็บ
js/config.js                   ค่าเชื่อมต่อ Supabase (Publishable key เท่านั้น)
supabase/schema.sql            โครงฐานข้อมูล (รันครั้งแรก)
supabase/trial_open_access.sql โหมดทดลองเดิม (v3 ปิดให้แล้ว)
supabase/v2_workflow.sql       Flow v2: Role ใหม่, งาน Normal/Special/PM-CAL
supabase/v3_auth.sql           ใช้งานจริง: Login Microsoft 365, ผู้ใช้ (app_users), ตรวจสิทธิ์ทุกขั้นในฐานข้อมูล
supabase/v3_trial_on.sql       โหมดทดลอง v3: เข้าด้วยอีเมลอย่างเดียว (ก่อน IT ตั้งค่า)
supabase/v3_trial_off.sql      ปิดโหมดทดลอง
docs/IT-Microsoft-Login.md     ขั้นตอนที่ IT ต้องตั้งค่า (ส่งไฟล์นี้ให้ IT)
supabase/functions/pmcal-reminders/  อีเมลเตือน PM/CAL รายวัน
supabase/schedule_reminders.sql ตั้งเวลาส่งอีเมลทุกวัน 08:00
```

## ติดตั้งฐานข้อมูล
ใน Supabase ให้ไปที่ **SQL Editor → New query** แล้วรันไฟล์ตามลำดับนี้ (ทุกไฟล์รันซ้ำได้)
1. `schema.sql`
2. `trial_open_access.sql`
3. `v2_workflow.sql`
4. `v3_auth.sql`
5. `v3_trial_on.sql` (ช่วงทดลองใช้ ก่อน IT ตั้งค่า Microsoft 365)

ถ้ารันไฟล์ใดซ้ำภายหลัง ต้องรันไฟล์ที่ลำดับถัดไปตามทุกครั้ง

### ช่วงทดลองใช้ → ใช้งานจริง
| | ช่วงทดลอง (ตอนนี้) | ใช้งานจริง |
|---|---|---|
| ฐานข้อมูล | รัน `v3_trial_on.sql` | IT ตั้งค่าเสร็จ → รัน `v3_trial_off.sql` |
| `js/config.js` | `TRIAL_LOGIN: true` | `TRIAL_LOGIN: false` |
| เข้าระบบ | กรอกอีเมลในรายชื่ออย่างเดียว (มีป้าย "โหมดทดลอง" ที่หัวเว็บ) | Microsoft 365 |
| สิทธิ์ / Flow | ตรวจในฐานข้อมูลเหมือนจริงทุกขั้น | เหมือนเดิม |

ช่วงทดลอง ใครรู้อีเมลคนอื่นก็เข้าในนามคนนั้นได้ ห้ามใส่ข้อมูลลับ
ถ้าต้องการล้างใบงานทดลองก่อนใช้จริง ให้รันใน SQL Editor: `truncate public.request_logs, public.requests;`

## เข้าระบบ
- กด **เข้าสู่ระบบด้วย Microsoft 365** แล้ว Login ด้วยบัญชี @scg.com
- เข้าได้เฉพาะอีเมลที่อยู่ในเมนู **ผู้ใช้** และติ๊ก **ใช้งาน** ไว้
- ขั้นตอนฝั่ง IT อยู่ใน [`docs/IT-Microsoft-Login.md`](docs/IT-Microsoft-Login.md)
- **ทางสำรอง (รับรหัสทางอีเมล):** ตั้ง `EMAIL_OTP: true` ใน `js/config.js`
  - ต้องเปิด Email provider และตั้ง SMTP ใน Supabase ก่อน
  - ใส่ `{{ .Token }}` ในเทมเพลตอีเมล Magic Link

## บทบาท
| บทบาท | หน้าที่หลัก |
|---|---|
| Member | เปิดใบงาน, แก้ไขเองแล้วปิดงาน, รับผิดชอบงาน Special ที่ได้รับมอบหมาย, รับผิดชอบงาน PM/CAL ของเครื่อง |
| Foreman Shift | เปิดใบงานแจ้งซ่อม, แก้ไขเองแล้วปิดงาน, แก้ไขและส่งใบงานที่ถูกตีกลับ |
| Foreman Day | อนุมัติหรือไม่อนุมัติใบงาน, เลือก Normal (RMT/FM) หรือ Special และมอบหมายงาน, สรุปผลงาน RMT/FM แล้วปิดงาน |
| Manager | อนุมัติ MEMO ตามลำดับ App 1 → 2 → 3, รับอีเมลเตือน PM/CAL ขั้น 3 |
| Admin | แจ้งซ่อมใน SAP/K2 และแนบหลักฐาน, ออก PO, จัดการเครื่องจักร, QR และผู้ใช้ |

Admin ตั้งค่าเพิ่มให้ผู้ใช้แต่ละคนได้ที่เมนู **ผู้ใช้** (หรือนำเข้าจากชีท `ผู้ใช้` ในแบบฟอร์ม Excel)

| ช่อง | ความหมาย |
|---|---|
| **FD ดูแลประเภท** | เครื่องจักร หรือ เครื่องทดสอบ ใบงานของเครื่องจักร Mold และอื่นๆ ไปหา FD เครื่องจักร ใบงานของเครื่องทดสอบไปหา FD เครื่องทดสอบ ถ้าไม่ระบุ = FD สำรองที่อนุมัติแทนได้ทุกประเภท |
| **Admin** | ให้สิทธิ์ Admin เพิ่มจากบทบาทหลัก เช่น Member + Admin |
| **อนุมัติ MEMO** | รายชื่อผู้อนุมัติ App 1–3 มาจากคนที่ติ๊กช่องนี้ |
| **ใช้งาน** | เอาติ๊กออกเพื่อปิดสิทธิ์ โดยประวัติในใบงานยังอยู่ |

## Flow ใบงาน
1. **มีผู้พบสิ่งผิดปกติ** → Member หรือ Foreman ออกไปดูหน้างาน แล้วเปิดใบงาน
   - **แก้ไขเองได้:** เลือก "แก้ไขเองได้แล้ว" บันทึกวิธีแก้ แล้วปิดงานทันที
   - **แก้ไขเองไม่ได้:** ระบุอาการ วิธีแก้ไขเบื้องต้น และความเร่งด่วน แล้วส่งให้ **Foreman Day** อนุมัติ
2. **Foreman Day ไม่อนุมัติ:** ใบงานกลับไปหาผู้เปิด เพื่อลองแก้ไขเองอีกครั้ง จากนั้นปิดงานเอง หรือส่งอนุมัติใหม่
3. **Foreman Day อนุมัติแบบ Normal:** เลือก **RMT** หรือ **FM**
   1. Admin แจ้งซ่อม (RMT ผ่าน SAP, FM ผ่าน K2) แล้วแนบเลขที่ใบแจ้งหรือรูปถ่าย
   2. RMT/FM ซ่อม
   3. Foreman Day สรุปผล (อะไหล่, วิธีการ, ค่าใช้จ่าย, ระยะเวลา) แล้วปิดงาน
4. **Foreman Day อนุมัติแบบ Special:** Foreman Day ทำเองหรือมอบหมาย Member
   1. ขอใบเสนอราคาจาก Vendor
   2. ออก MEMO และเลือกผู้อนุมัติ App 1–3 ตามลำดับ
   3. Manager อนุมัติทีละคน ถ้ามีคนไม่อนุมัติ ใบงานจะกลับไปให้แก้แล้วส่งใหม่ตั้งแต่ App 1
   4. Admin ออก PO และผู้รับผิดชอบนัดวัน Vendor เข้าซ่อม
   5. สรุปผลแล้วปิดงาน (ปิดได้หลังบันทึก PO แล้ว)
5. **PM/CAL:** ใช้ Flow แบบ Special โดยมี Member ผู้รับผิดชอบเครื่องเป็นคนดำเนินการ
   - ระบบเปิดใบงานให้อัตโนมัติเมื่อเหลือ 90 วันก่อนครบกำหนด
   - เมื่อปิดงาน ระบบอัปเดตวันที่ทำ PM/CAL ล่าสุดของเครื่องให้

## การแจ้งเตือน PM/CAL
- **ขั้น 1 (≤ 3 เดือน):** Member ผู้รับผิดชอบ
- **ขั้น 2 (≤ 2 เดือน):** + Foreman Day
- **ขั้น 3 (≤ 1 เดือน):** + Manager
- ส่งอีเมล **ทุกวัน** จนกว่า Member จะกด **"เริ่มดำเนินการแล้ว"** ในใบงาน (หรือส่ง MEMO)
- ขั้น 2 ส่งถึง Foreman Day ตามประเภทของเครื่อง
- ในเว็บมีแถบเตือนสีแดงที่หน้าหลักของผู้ที่เกี่ยวข้องอยู่แล้ว
- อีเมลยังต้องตั้งค่าเพิ่ม ดูหัวข้อถัดไป

### เปิดอีเมลเตือน (ทำครั้งเดียว · ยังไม่ได้ทดสอบกับระบบจริง)
1. **สมัคร Brevo (ฟรี 300 ฉบับ/วัน)** ที่ brevo.com
   - ยืนยันอีเมลผู้ส่งที่ **Senders**
   - สร้าง API key ที่ **SMTP & API → API Keys**
2. **สร้าง Edge Function** ใน Supabase ที่ **Edge Functions → Deploy a new function → Via Editor**
   - ตั้งชื่อ `pmcal-reminders`
   - วางโค้ดจาก `supabase/functions/pmcal-reminders/index.ts` แล้วกด Deploy
   - ใน **Details** ของฟังก์ชัน ให้**ปิด Verify JWT**
3. **ตั้ง Secrets** ที่ **Edge Functions → Secrets**
   - `BREVO_API_KEY`
   - `MAIL_FROM` (อีเมลผู้ส่งที่ยืนยันแล้ว)
   - `APP_URL` = `https://phatphisut2011-svg.github.io/capd-maintenance/`
   - `CRON_SECRET` (ตั้งข้อความยาวๆ เอง)
4. **ตั้งเวลาส่ง**
   - ที่ **Database → Extensions** เปิด `pg_cron` และ `pg_net`
   - รัน `supabase/schedule_reminders.sql` โดยใส่ค่า `CRON_SECRET` เดียวกับข้อ 3

## QR Code ติดเครื่องจักร
- **พิมพ์:** Admin ไปที่ **เครื่องจักร → พิมพ์ QR ทั้งหมด** (หรือกดปุ่ม **QR** รายเครื่อง)
- **สแกน:** สแกนด้วยกล้องมือถือ (ถ้ายังไม่ได้ Login ระบบจะให้ Login ก่อน) จะเปิด **Dashboard ของเครื่อง**
  - มีปุ่มแจ้งซ่อมและรายการใบงานที่ค้าง
  - สรุป 12 เดือน: จำนวนครั้งที่ซ่อม, Downtime, MTTR, ค่าซ่อม, ค่า PM/CAL และกราฟรายเดือน
  - แผน PM/CAL, เอกสารของเครื่อง, ประวัติการซ่อมทั้งหมด
- กดรหัสเครื่องในหน้า **เครื่องจักร** ก็เปิด Dashboard เดียวกัน
- ถ้าเปลี่ยนที่อยู่เว็บ ต้องพิมพ์ QR ใหม่

## นำเข้าข้อมูล
- **ไฟล์ที่ใช้:** แบบฟอร์ม `CAPD-Maintenance-Data-Template.xlsx`
- **นำเข้าเครื่องจักร:** Admin ไปที่ **เครื่องจักร → นำเข้าจาก Excel**
  - **ชีท `Machine Master`:** อ่านข้อมูลเครื่อง พร้อมคอลัมน์ `PM DATE`, `PM Interval`, `CAL DATE`, `CAL Interval` ในชีทเดียวกัน
  - **ชีท `ผู้ใช้`:** นำเข้าด้วย ถ้ามีในไฟล์
  - **ไฟล์ `DATA.xlsx` เดิม:** ยังใช้ได้ (ชีท `PM Master` และ `CAL Master`)
- **นำเข้าผู้ใช้อย่างเดียว:** ไปที่ **ผู้ใช้ → นำเข้าผู้ใช้จาก Excel**
- **วันที่:** ใช้รูปแบบวันที่ของ Excel หรือพิมพ์ `วว/ดด/ปปปป` (ปี พ.ศ. ได้)
- **การข้ามข้อมูล:** แถวที่รหัสเครื่องขึ้นต้นด้วย `ตัวอย่าง` จะถูกข้าม
- **Eng,Foreman:** ถ้าว่างหรือเป็นข้อความผิดพลาด ระบบใส่ Foreman Day ตามประเภทเครื่องให้
- **Responsibility:** ใส่**อีเมล** Member เพื่อให้ระบบมอบงาน PM/CAL และส่งอีเมลเตือนได้
- **นำเข้าทีหลัง:** ชีท Vendors, Spare Parts, จุดวัดไฟ และทะเบียนเอกสาร จะนำเข้าได้ในระยะ 2
